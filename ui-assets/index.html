      Switchyard reference
      
        
      
      
      
      
        
      Modes
      
        
        
          
      • The chrome's Microgrids / Scenarios buttons swap the main pane. The REPL drawer stays visible in both. Press 1 for Microgrids, 2 for Scenarios.
        • 
          
      • Mode preference persists in localStorage; refresh restores the last-picked mode + last-selected microgrid.
        • 
        
      
        
      Microgrids
      
        
        
          
      • The Microgrids mode opens a card grid of every registered microgrid (one per (make-microgrid …) form, plus any added via the + New microgrid card or POST /api/microgrids/create).
        • 
          
      • The ⇪ Import site… card creates a microgrid from a microgrid API site export: pick components.json and connections.json together (connections optional). Rated power bounds, battery capacity, SoC range and the grid's rated fuse current all carry over into the simulation.
        • 
          
      • Clicking a card drills into that microgrid's Dashboard + Topology sub-tabs. The ← Microgrids button in the header returns to the list; a small → name chip on the REPL form shows which microgrid the REPL's evals route to.
        • 
          
      • Each microgrid runs its own Microgrid gRPC server on [::1]:<port> (default 8800, 8810, 8820, …). PlatformAssets runs on a single shared port (default 9900).
        • 
          
      • Component ids are globally unique across the enterprise — copying a selection from one microgrid and pasting into another (Ctrl/Cmd+V) re-creates the structure with fresh ids.
        • 
        
      
        
      Dashboard
      
        
        
          
      • Pool tiles (top row) — grid, battery pool, PV, consumer, producer. Each tile renders a 15-minute sparkline + the formula tree on click.
        • 
          
      • Battery pool envelope — lower → upper bounds line under the pool reading, derived from BatteryPool::power_bounds.
        • 
          
      • Battery rows — each battery row pairs with the inverter it's wired to (looked up via successor edges). Battery cell: name + health + SoC bar + DC W; inverter cell: name + subtype + health + envelope visual (lower / measured / upper). Sort by SoC ascending. Click either cell to flip to Topology with the node selected.
        • 
          
      • PV rows — solar inverters only, same envelope shape as the inverter half of a battery row.
        • 
          
      • EV / CHP rows — own section each: name + health + SoC (EV only) + power readout.
        • 
        
      
        
      Aggregations
      
        
        
          
      • Pool tiles read from the same frequenz-microgrid client a production control app would use. Click any tile to open the formula tree in the inspector — each #N is a link back to the topology canvas.
        • 
          
      • Pulse-bar pills — graph (✓ / ⚠) summarises validation warnings from frequenz-microgrid-component-graph; loopback is the Microgrid client status; density + TZ toggle visual options.
        • 
        
      
        
      Snapshots
      
        
        
          
      • Snapshots button (top right) — saves the selected microgrid's managed file under snapshots/<microgrid-id>/<name>.lisp; load to replay that state. Needs a selected, managed microgrid. Headless: swctl snapshot save / load / list [--microgrid-id N].
        • 
        
      
        
      Topology canvas
      
        
        
          
      • Click a node — inspect it (charts + config + knobs in the floating inspector; click empty canvas or Esc to dismiss).
        • 
          
      • Shift+Drag on empty canvas — rubber-band a selection rectangle; nodes inside the box are selected.
        • 
          
      • Shift+Click a node — toggle that node into / out of the current selection (after a rubber-band, or to build one a node at a time).
        • 
          
      • Ctrl/Cmd+hold + drag from one node to another — create an edge between them.
        • 
          
      • Double-click a node — select it together with everything it feeds (its whole subtree). Shift+Double-click adds the subtree to the selection.
        • 
          
      • Right-click — context menu. With a selection: Copy, Cut, Delete. With two or more nodes selected, the menu grows the arrange tools: align as a grid / lanes / radial, align in a row / column, spread, mirror, and spacing. With nothing selected and a non-empty clipboard: Paste. Right-clicking a node not in the current selection resets the selection to that node first.
        • 
          
      • Layout picker (top-right of the canvas) — lanes (default), columns, top-down, radial. Dragging a node by hand keeps your arrangement; picking a layout resets it. The snap toggle makes dragged nodes snap to a grid; hold Alt while dragging to move along one axis only.
        • 
          
      • Ctrl/Cmd+C — copy selection. Ctrl/Cmd+V — paste. Ctrl/Cmd+X — cut. Each paste re-uses the last copy; clipboard captures structure only (categories + internal edges), so clones use category defaults.
        • 
          
      • Del / Backspace — delete selection. Ctrl/Cmd+A — select all visible. Esc — deselect.
        • 
          
      • Ctrl/Cmd+Z — undo the last canvas edit. Ctrl/Cmd+Shift+Z (or Ctrl/Cmd+Y) — redo. The history lives on the server, one step per structural edit of the microgrid's managed file, so it survives page reloads and is shared by every open tab.
        • 
        
      
        
      Formulas
      
        
        
          
      • The Formulas sub-tab explains the formulas the frequenz-microgrid-component-graph engine generates for this microgrid. Pick a metric on the right; the formula renders from the engine's own AST.
        • 
          
      • Hover a part of the formula for its reason; click it to open that reason in the Why drawer at the bottom. A #N selects that component on the canvas.
        • 
          
      • Hovering a row in the Why tree highlights its components in the formula and on the canvas. Subtracted parts show red.
        • 
          
      • The canvas is for looking and arranging only — no structural editing. The arrange tools live in the right-click menu, same as on Topology.
        • 
          
      • T (or the right-click menu) turns the selection's telemetry off and on. It works by changing the operational mode, keeping the control capability as it is. A component without telemetry has no reading, so the formula routes around it through its fallbacks. This is a config edit: it persists, and Ctrl/Cmd+Z on the Topology tab undoes it.
        • 
          
      • copy copies the plain formula string; copy with comments copies it with the reasons as // comments.
        • 
          
      • The Engine options card (collapsed by default) changes how the formula is generated and how strictly the graph is validated. The graph building flags accept graphs the engine would normally reject — unconnected components, failed component validation, untyped inverters. All options are view-local: nothing is stored on the server.
        • 
        
      
        
      Inspector + chrome
      
        
        
          
      • Inspector — a floating panel on the right. It appears when you click a node (charts + config + knobs) or a Dashboard tile (formula tree), and closes when you click empty canvas, press Esc, hit its ×, or switch tab.
        • 
          
      • Add component — the + Add button at the top-left of the Topology canvas opens a palette: click a category and an auto-id'd component appears, with a color dot matching its node's category colour. Wire it via Ctrl/Cmd+drag.
        • 
          
      • Values — nodes show current power (and reactive power or SoC), edges a chevron in the direction power actually flows, sized by magnitude. The values pill (top right) toggles the numbers; off, nodes show name and id only. Hovering a node on Topology opens a detail card.
        • 
          
      • Defaults — per-category defaults (Lisp values), opened in the inspector; edits write to enterprise.lisp.
        • 
          
      • Managed files — every microgrid is a file. A managed one (created here, or adopted) carries a switchyard-generated block that is rewritten on each structural edit; an unmanaged one is hand-written, so its structure is read-only in the UI and its card carries an unmanaged chip. Hit Adopt in the microgrid header to take it over. An unsaved chip means a live edit the file could not record.
        • 
        
      
        
      REPL
      
        
        
          
      • Ctrl/Cmd+Enter — eval. Tab — complete.
        • 
          
      • Drag the splitter between the topology row and the drawer to resize; double-click it to collapse the drawer to just the REPL input.
